# bvs-camera — видеопередатчик на Raspberry Pi

Бортовая часть проекта «Сквозь помехи»: Camera V2 → Raspberry Pi → H.264/MJPEG →
RTP → WFB-ng (шифрование и FEC). Обратные метрики НСУ используются для выбора
разрешения, FPS, битрейта, FEC и MCS.

Приём, декодирование и браузерный просмотр находятся в отдельном репозитории
[Through-interference/nsy-server](https://github.com/Through-interference/nsy-server).
Этот проект не требует исходников НСУ или прежней папки `video-link`.

Для приоритетной демонстрации телеметрии ≥300 кбит/с есть отдельный режим без
камеры: `bash start-telemetry.sh --interface wlan1 --plan`. Он принимает UDP
бортового компьютера и поддерживает обратные UDP-команды, поиск резервной частоты
и сбор протокола испытаний. Запуск на железе и границы подтверждения 3 км описаны
в [инструкции приёмки](docs/TELEMETRY_ACCEPTANCE.md).

## 1. Подключение и получение проекта

Ориентир: Raspberry Pi 4B, Camera V2/IMX219, 64-битная Raspberry Pi OS.

```bash
ssh pomehi@pomehi.local
sudo apt-get update
sudo apt-get install -y git
git clone https://github.com/Through-interference/bvs-camera.git
cd ~/bvs-camera
bash scripts/install-pi.sh
```

Если репозиторий приватный, предварительно настройте доступ к GitHub на Pi.
Альтернатива — скопировать checkout с ноутбука; инструкция в
[docs/INSTALL.md](docs/INSTALL.md). Пароли, GitHub-токены и ключи не входят в проект.

## 2. Проверка камеры

```bash
rpicam-hello --list-cameras
rpicam-vid -n -t 3000 --width 1280 --height 720 --framerate 30 \
  --codec h264 --inline -o /tmp/bvs-camera-check.h264
ls -lh /tmp/bvs-camera-check.h264
```

В списке должен быть `imx219`. Если камера не определяется, сначала проверьте
шлейф и разъём CAMERA при отключённом питании. Настройки firmware автоматически
не перезаписываются.

Не запускайте две программы захвата одной камеры одновременно.

Контроллер проверяет процесс захвата и свежесть RTP. После остановки камеры или отсутствия полного кадра более 5 секунд он повторно применяет текущий профиль, включая ручной режим. Между неудачными попытками выдерживается пауза 3 секунды; первые 2,5 секунды после успешной смены профиля отведены на запуск. После долгого применения профиля обратный канал передаёт контроллеру последнюю накопленную UDP-метрику.

## 3. Парные ключи

При первом развёртывании создайте одну пару на доверенной машине:

```bash
bash scripts/generate-link-keys.sh
mkdir -p keys/drone1
chmod 700 keys keys/drone1
install -m 600 keys/pair/drone.key keys/drone1/drone.key
```

- `drone.key` используется только бортовым передатчиком/приёмником.
- Соответствующий `gs.key` передайте на НСУ в `nsy-server/keys/drone1/gs.key`.
- Если рабочая пара уже есть, перенесите её, а не создавайте новую на одном конце.
- Скрипт отказывается перезаписывать существующую пару. `keys/` исключён из Git.

## 4. Выберите транспорт

| Режим | Для чего | Что требуется |
|---|---|---|
| `radio` | Прямые кадры WFB через monitor/injection, без точки доступа | Выделенный адаптер, поддерживающий драйвер, одинаковые частоты и ключи |
| `ip` | WFB/FEC поверх обычной IP-сети | IP-доступ между бортом и НСУ; соединение инициирует НСУ |

### Прямой WFB через внешний адаптер

Сначала выполните [настройку драйвера и выделенного интерфейса](docs/RADIO.md).
Не переключайте адаптер, через который идёт единственное SSH-подключение.
Для настройки используйте отдельный Ethernet или другой канал управления.

```bash
sudo bash start-air.sh --mode radio --interface wlan1
```

`wlan1` — пример: укажите имя именно внешнего адаптера. Launcher проверяет
драйвер и отсутствие глобального сетевого IP, затем выставляет monitor/HT20.
На НСУ нужно запустить соответствующий radio-режим `nsy-server`.

### WFB поверх обычной IP-сети

```bash
bash start-air.sh --mode ip --bind PI_WIFI_IP --peer NSU_WIFI_IP
```

Замените `PI_WIFI_IP` и `NSU_WIFI_IP` реальными IPv4-адресами. На НСУ:

```bash
# Выполнить из репозитория nsy-server:
bash start-nsu.sh --mode ip --bind NSU_WIFI_IP --peer PI_WIFI_IP
```

По умолчанию UDP-порт внешнего транспорта — `17030`; его можно задать с обеих
сторон через `--network-port`. НСУ посылает keepalive первой, что позволяет
работать через stateful firewall/NAT без произвольного входящего видеопорта.
Фильтрация внешнего peer делается по IP; защита содержимого обеспечивается WFB.

**В `ip`-режиме RSSI/SNR не подставляются из debug-заголовка, а MCS не управляет
физическим Wi-Fi.** Радиорежимы здесь выбирают ОС/точка доступа; FEC, шифрование
и изменение параметров камеры действительно работают. Это не доказательство
monitor/injection, дальности или характеристик MCS в эфире.

## 5. Состояние и управление

Контроллер Pi слушает только `127.0.0.1:8090`. Для доступа с ноутбука:

```bash
ssh -N -L 18090:127.0.0.1:8090 pomehi@pomehi.local
```

Откройте http://127.0.0.1:18090/status или выполните:

```bash
curl http://127.0.0.1:18090/status
curl -H 'Content-Type: application/json' -d '{"profile":"high"}' \
  http://127.0.0.1:18090/profile
curl -H 'Content-Type: application/json' -d '{"enabled":true}' \
  http://127.0.0.1:18090/auto
```

Ctrl+C в терминале передатчика завершает дочерние процессы. `--seconds 60`
ограничивает тест по времени. Логи — `results/air/`; `--log-dir` меняет каталог.
Для запуска из другого рабочего каталога укажите полный путь к `start-air.sh`.

## Профили камеры

| Профиль | Кодек | Размер | Запрошенный FPS | Битрейт | MCS / FEC |
|---|---|---|---:|---:|---|
| critical | MJPEG | 320×240 | 5 | JPEG quality 30 | 0 / 4:8 |
| low | H.264 | 640×480 | 30 | 0,8 Мбит/с | 0 / 8:12 |
| medium | H.264 | 1280×720 | 45 | 2,5 Мбит/с | 1 / 8:12 |
| high | H.264 | 1280×720 | 60 | 5 Мбит/с | 2 / 8:10 |

Профиль `fast` — отдельный ручной эксперимент 640×480 с запросом 200 FPS,
не обещание такой частоты на экране. Переходы сейчас перезапускают камеру и
могут давать паузу. Без обратной связи автоматика переходит в critical.
Параметры требуют калибровки; 3 км, 10 Мбит/с и <50 мс не объявлены достигнутыми.

```text
src/bvs_camera/   камера, контроллер, передатчик и обратные метрики
config/link.json  ID/частота/полоса канала
scripts/         установка, запуск модулей, ключи и тесты
systemd/         пример службы Raspberry Pi
tests/           проверки без физической камеры и радио
docs/            установка, радионастройка, протокол и результаты
```

```bash
bash scripts/test.sh
bash scripts/run-module.sh air_station --help
```

Код не требует установки через pip: скрипты задают абсолютный `PYTHONPATH`.
Для pip предусмотрены `pyproject.toml` и `setup.cfg`; GStreamer/GI и rpicam
устанавливаются системными пакетами.
